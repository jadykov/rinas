# Сайт-витрина мастерской кашпо

Мастерская делает кашпо (подставки и корпуса под цветочные горшки) из массива дерева.
Работают вдвоём, вручную. Позиционирование: **кастом, любой размер, любая сложность**. Не «дёшево».

Сайт — витрина и портфолио. Единственное целевое действие — **оставить заявку**.

**Полное ТЗ: `docs/PLAN.md`. Читай его перед началом каждой новой фазы.**

---

## Правила работы

1. **Не менять стек.** Если что-то не получается — сообщи, не подменяй технологию.
2. **Одна задача = один файл.** Путь указан в задаче. Не трогай файлы, которые не указаны.
3. **Не обновлять зависимости** без явной просьбы. Версии в `package.json` — точным числом, без `^` и `~`.
4. **Не выдумывать данные.** Тексты, цены, названия изделий берутся из базы. Никакого lorem ipsum и вымышленных товаров.
5. **Не рапортовать «готово», не запустив.** Выполни то, что написал: сборку, запрос, открытие страницы. Не можешь проверить — так и скажи.
6. **Git:** коммит после каждой завершённой фазы. В `.gitignore`: `.env`, `pb_data/`, `node_modules/`, `dist/`.
7. **Язык:** интерфейс, тексты, поля форм, ошибки, комментарии в коде — на русском. Цены в рублях.
8. **Mobile first.** Сначала мобильная вёрстка (360–430 px), потом десктоп.

## Стек (зафиксирован)

| Слой | Технология |
|---|---|
| Фронт | **Astro**, SSR-режим, адаптер `@astrojs/node` |
| Бэкенд + CMS | **PocketBase** (Go-бинарник, SQLite) |
| Прокси + HTTPS | **Caddy** |
| Оркестрация | **docker-compose** |
| Стили | Обычный CSS с переменными, без фреймворков |
| 3D | `@google/model-viewer` |
| Сервер | VPS в РФ, Ubuntu 22–24 |

Не предлагать Next.js, React, Vue, Tailwind, headless CMS, WordPress.

## Чего в проекте НЕТ

Не предлагать и не делать:

- Корзину, checkout, онлайн-оплату, эквайринг — **оплата только лично, переводом**
- Личный кабинет, регистрацию, авторизацию на фронте
- Telegram-бота с каталогом и приёмом заказов
- ИИ-чат и ИИ-консультанта на сайте
- Контекстную рекламу и связанные интеграции (товарные фиды, ЕРИР)
- Мультиязычность, тёмную тему

## Запуск и сборка

- Поднять инфраструктуру: `docker compose up -d --build` (в корне `/rinas`).
- Frontend — Astro SSR в `web/`, выходной артефакт `web/dist/server/entry.mjs`.
- Контейнер `web` запускает `node dist/server/entry.mjs` — серверный рендеринг идёт из сборки, не из dev-режима.
- Сборка frontend (`npm install`, `npm run build`) выполняется **внутри Docker-контейнера** (`docker run --rm -v "$PWD/web:/app" -w /app node:24-alpine ...`) — в песочнице разработки DNS на хосте не работает.
- Кэш `node_modules` и `dist` — не коммитить (уже в `.gitignore`).
- `PUBLIC_PB_URL` для SSR не задан — берётся дефолт `http://pocketbase:8090` (имя сервиса в docker-сети), см. `web/src/lib/pb.ts`.
- Для локальной проверки порты проброшены только на `127.0.0.1`: админка PocketBase — `http://localhost:8090/_/`, фронт — `http://localhost:4321/catalog`. На прод `ports` у `pocketbase` и `web` убрать, наружу пускать только Caddy.

## Структура frontend

- `web/src/pages/*` — страницы Astro (SSR).
- `web/src/lib/pb.ts` — клиент PocketBase (серверный, без публикации в браузер).
