# Полное ТЗ: сайт-витрина мастерской кашпо

Правила работы и стек — в `AGENTS.md` в корне репозитория. Здесь — что именно делаем.

---

## 1. Контекст бизнеса

Мастерская делает **кашпо** — подставки и корпуса под цветочные горшки из массива дерева. Работают вдвоём, вручную, производственная мощность ограничена.

**Позиционирование:** кастом, любой размер, любая сложность. Сознательно не «дёшево» — при ограниченной мощности конкуренция ценой вредна, дешёвые заказы забивают месяц и вытесняют дорогие.

**Цель сайта:** не гнать массовый трафик, а показать уровень работ и собрать заявки на индивидуальные заказы.

**Главная страница по деньгам — `/custom`**, а не каталог. Каталог — это портфолио и база под поисковый трафик.

---

## 2. Структура сайта

| URL | Назначение |
|---|---|
| `/` | Лендинг: оффер про кастом → 6–8 лучших работ → «как заказать» в 4 шага → фото мастерской → отзывы → форма заявки |
| `/catalog` | Все работы, фильтр по диаметру горшка и типу |
| `/catalog/[slug]` | Карточка работы, свой URL — отсюда идёт органика |
| `/custom` | **Ключевая страница.** Форма кастом-заказа: размеры, загрузка фото интерьера и референсов |
| `/info` | Доставка, оплата, сроки, наличие, уход за деревом |
| `/about` | Мастера, цех, процесс производства |
| `/privacy` | Политика конфиденциальности — обязательна по закону при сборе имени и телефона |

Наличие товара показывать в `/info` и в карточке, но не выносить на главную: основной режим работы — под заказ.

## 3. Модель данных (PocketBase)

Создаётся руками через админку `/_/`, не кодом — быстрее и надёжнее. Менять потом больно, сверь поля перед созданием.

### `products`

| Поле | Тип | Примечание |
|---|---|---|
| `title` | text | Название работы |
| `slug` | text, unique | ЧПУ, латиница: `kashpo-napolnoe-dub-30` |
| `description` | editor | Описание, rich text |
| `price_from` | number | «от N ₽», может быть пустым |
| `pot_diameter_min` | number | см, для фильтра |
| `pot_diameter_max` | number | см, для фильтра |
| `height` | number | см |
| `width` | number | см |
| `material` | select | дуб / ясень / сосна / орех / комбинированное |
| `type` | select | напольное / настольное / подвесное / на стену |
| `photos` | file, multiple | Главное фото — первое в списке |
| `model_3d` | file, single | `.glb`, необязательное |
| `in_stock` | bool | |
| `lead_time_days` | number | Срок изготовления |
| `is_featured` | bool | Показывать на главной |
| `sort_order` | number | Ручная сортировка |
| `seo_title` | text | Если пусто — генерится из `title` |
| `seo_description` | text | Если пусто — берётся начало `description` |

### `leads`

`name` (text), `contact` (text — телефон / TG / почта), `message` (text), `product` (relation → products, необязательно), `attachments` (file, multiple), `source` (text — UTM или страница), `status` (select: новая / в работе / отказ / сделана)

### `reviews`

`author` (text), `text` (text), `photo` (file), `rating` (number 1–5), `is_published` (bool)

### `pages`

`slug` (text, unique), `title` (text), `content` (editor) — чтобы править тексты «Доставки» и «О нас» без деплоя.

### Права доступа

- `products`, `reviews`, `pages` — **List/View: public**, создание и правка только админ
- `leads` — **Create: public**, чтение **только админ**. Никогда не отдавать список заявок наружу.

## 4. Фазы работы

Каждая фаза заканчивается рабочим состоянием и коммитом. Не начинать следующую, пока предыдущая не проверена глазами.

### Фаза 1. Инфраструктура и деплой

**Деплой делается первым, до кода.** Иначе на финише выяснится, что на проде не заводится.

- `docker-compose.yml`: сервисы `pocketbase`, `web`, `caddy`
- `Dockerfile` для PocketBase: скачать релиз с GitHub, распаковать, том на `/pb_data`
- `Caddyfile` с доменом и автоматическим HTTPS
- `web` пока отдаёт заглушку «Скоро открытие»

**Готово, когда:** домен открывается по HTTPS, админка PocketBase доступна на `/_/`, создан аккаунт администратора.

Ориентир для `Caddyfile`:

```
ДОМЕН.ru {
    handle /api/* {
        reverse_proxy pocketbase:8090
    }
    handle /_/* {
        reverse_proxy pocketbase:8090
    }
    handle {
        reverse_proxy web:4321
    }
}
```

### Фаза 2. Данные

Создать коллекции из раздела 3 через админку. Настроить права. Завести 2–3 тестовых изделия с фото.

**Готово, когда:** `GET /api/collections/products/records` возвращает записи без авторизации.

### Фаза 3. Каталог без дизайна

Инициализировать Astro, подключить SSR-адаптер Node, написать клиент к PocketBase (`src/lib/pb.ts`), вывести `/catalog` простым списком. Голый HTML, стили не трогать.

**Готово, когда:** список товаров из базы виден в браузере.

После этой фазы имеет смысл запустить `/init` — появилась реальная структура папок, команда допишет в `AGENTS.md` build-команды и конвенции проекта.

### Фаза 4. Карточка товара

`/catalog/[slug]`, галерея фото, характеристики, кнопка «Заказать похожее» → ведёт на `/custom` с подставленным товаром. Честный 404 для несуществующего slug.

### Фаза 5. Дизайн и адаптив

Отдельной фазой, не смешивая с логикой. Мобильная вёрстка первой.

Ориентир по стилю: много воздуха, крупные фото, тёмный текст на светлом фоне, один акцентный цвет, шрифт с характером в заголовках. Фотографии должны занимать больше места, чем текст — товар продаётся глазами.

### Фаза 6. Формы и заявки

- Форма на `/`, `/custom`, в карточке товара
- Загрузка файлов на `/custom` (фото интерьера, референсы)
- Отправка → запись в `leads` → уведомление в Telegram
- **Чекбокс согласия на обработку персональных данных** со ссылкой на `/privacy` — обязателен, иначе штраф
- Honeypot-поле против спам-ботов
- Понятное состояние после отправки: «Заявка отправлена, свяжемся в течение дня»

Уведомление в Telegram: бот создаётся у `@BotFather`, токен и chat_id — в `.env`, отправка POST-запросом на `https://api.telegram.org/bot<TOKEN>/sendMessage`. Никаких библиотек, это один `fetch`.

Плюс кнопка «Написать в Telegram» на сайте — часть людей никогда не заполнит форму, но напишет в мессенджер.

### Фаза 7. SEO

- `sitemap.xml`, `robots.txt`, `canonical` на всех страницах
- `<title>` и `<meta description>` из полей товара
- Open Graph и `og:image` (первое фото товара)
- **JSON-LD разметка `Product`** в карточке — даёт расширенный сниппет в Яндексе и Google
- H1 человеческим языком: «Напольное кашпо из массива дуба под горшок 30 см»
- Заголовок и текст `/custom` под запросы: «кашпо на заказ», «кашпо по своим размерам», «кашпо нестандартного размера»

### Фаза 8. 3D

`@google/model-viewer` в карточке товара, если заполнено поле `model_3d`.

**Загружать модель только по клику на кнопку «Смотреть в 3D»**, не при открытии страницы — иначе убивается скорость загрузки, а это фактор ранжирования. До клика — превью-заглушка.

Как получить модели: снять изделие телефоном через Polycam или RealityScan (фотограмметрия, 20–30 минут на предмет), сжать `gltf-transform` до 2–5 МБ, залить в поле `model_3d`. Делать на 3–5 топовых работ, не на весь каталог.

### Фаза 9. Финал

- Яндекс.Метрика + цели: отправка формы, клик по кнопке Telegram
- Яндекс.Вебмастер, отправить sitemap
- Прогон Lighthouse: цель Performance ≥ 90 на мобильном
- Скрипт бэкапа `pb_data` по cron

## 5. Подборщик вместо ИИ-консультанта

ИИ-чата на сайте нет. Вместо него — фильтр на `/catalog`: **диаметр горшка → высота → тип → показать подходящие работы**.

Обычный фильтр по полям, никакой модели не нужно. Он снимает главное возражение покупателя: «а влезет ли мой горшок».

---

## 6. Фотографии

Есть профессиональные RAW-исходники от фотографа. Это главный актив проекта — ценнее всего кода.

Что запросить у фотографа:

- JPEG, длинная сторона 2000 px, качество 85 — исходники для сайта
- **Вертикальные кропы 4:5** тех же кадров — для карточек каталога и соцсетей
- 3–5 кадров **в интерьере, с растением и предметом для масштаба** — важнее студийных
- Макро на фактуру дерева и на стыки — они доказывают «любую сложность» лучше текста

Ресайз и конвертацию в WebP делает PocketBase на загрузке (параметр `thumb`). Отдельно не возиться.

## 7. Трафик (контекст, не задача для агента)

Сайт не приносит продажи сам по себе, он конвертирует приведённый трафик.

1. **Авито** — уже работает, самый дешёвый источник. Каждую работу отдельным объявлением с разными заголовками, плюс отдельное объявление на кастом.
2. **VK и Telegram-канал** — переливать туда аудиторию из Instagram. Instagram заблокирован в РФ с 2022 года, Meta признана экстремистской организацией, реклама на её площадках в РФ запрещена. Опираться на этот канал нельзя, ссылку на него на сайте не ставить.
3. **Короткие вертикальные видео процесса** — распил, шлифовка, масло на дереве, финал с растением. Лучшее доказательство «любой сложности». Один съёмочный день даёт контент на месяц.
4. **Pinterest** — недооценённый источник интерьерного трафика, в России работает.
5. **SEO** — первые органические заявки через 4–6 месяцев, не раньше. Главная цель — `/custom` по низкочастотным запросам про индивидуальный заказ: конкуренции почти нет, приходят ровно нужные клиенты.

Контекстная реклама сознательно не запускается: мощность ограничена двумя людьми, поток заявок сверх мощности вреден.
